### P1-1, CURED — the strict parser panicked instead of refusing

`rejectDuplicateJSONKeys` discarded the error of `dec.Token()` and asserted the
key (`k := kt.(string)`). The auditor reproduced it with the COMPILED BINARY in
a separate OS process: `korvun intent create-v2` over a file with one stray
comma died with `panic: interface conversion: json.Token is nil, not string`.
Worse, the same bytes reach `ResolveIntentV2` through a corrupt
`canonical_terms` row, so corruption crashed the very path whose job is to fail
closed — captured with a second real connection rewriting the row.

Cure: the key token is JUDGED. A scanner error, a non-string key, a truncated
document and anything else the walk cannot finish come back as the new named
sentinel `ErrIntentMalformed`; a repeated key keeps `ErrIntentDuplicateField`.
One taxonomy out of the scanner, no panic.

Mould: `TestIntentV2_MalformedBytesAreRefusedNotPanics`, six rows including the
auditor's four, each with `recover()` so a panic is a failure and not a crash.
Probing mutation — restore the assertion — and its red:

```text
--- FAIL: TestIntentV2_MalformedBytesAreRefusedNotPanics
    --- FAIL: …/{"intent_id":"int_x","schema_version":2,}
    --- FAIL: …/{1:2}
    --- FAIL: …/{"a":{2:3}}
    --- FAIL: …/{"intent_id":"x",}
```

### P1-2, CURED — a REVOKED legacy consent came back as signed, ACTIVE terms

FR-INT-10 says a revoked root is never silently recreated. `ImportLegacyIntentV2`
never read `legacy.Status`, so `korvun intent adopt-root` over a REVOKED v1 root
returned exit 0 and left a signed version 2, ACTIVE, carrying EVERY effect class
including `critical` and `write_irreversible`. A human's withdrawal of consent
was manufactured back into consent.

Cure: the legacy lifecycle is read before the terms are translated. Only ACTIVE
may be carried forward; REVOKED, EXPIRED and anything else are refused BY NAME
(`ErrIntentRevoked`, `ErrIntentExpired`, `ErrIntentInactive`), and the refused
import returns no terms.

Mould: `TestImportLegacyIntentV2_RefusesConsentThatIsNotActive`, one row per
lifecycle, each demanding ITS sentinel. Probing mutation — delete the lifecycle
switch — reddens all four rows. Declared test-fixture repair: the existing
import test built a legacy contract with an empty `Status`, a field production
now judges; the fixture states `ACTIVE`.

### What is NOT cured, and why this train stops

Eleven P2 stand, each with the auditor's capture. Summarised so nobody has to
reconstruct them:

1. **No mould for the signature check at use.** Neutralising only

   the canto's AS-INT-03 mutation moved two branches at once and the red came
   from the digest comparison. The guarantee HOLDS in the delivered code; the
   red that proves it does not exist.

   verification branch — the auditor confirmed the asymmetry is real and not a

   the head behind keeps it GREEN, its fixture wires no receipt sealer at all

3. **`TestIntentV2_ClosedStoreReturnsInfrastructureErrors` cannot fail** for

   leave the whole package green.
4. **FR-INT-05 is literally false.** A signer that mutates a slice-backed field
   IN PLACE defeats the post-sign comparison (both sides read the same array):
   `ActivateIntentV2` commits rows and reports success, and the intent is

5. **`GetIntentV2` and `GetIntentAnyVersion` return tampered terms with

9. **A benign race is reported as corruption**: `ResolveIntentV2` reads the head

10. **"Tampered terms fail at use" is an unscoped absolute**: the key registry
