# V0151-A — the three P1 of the seventeenth pass, cured as a class

Block A of v0.15.1. The claim refuses a purge that does not hold inside its
own transaction; a webhook_call closes on the ONE class the wire can support;
the crash pass closes only what it owns. Plus P2-4, moved into this block by

and is written down: single consumption does NOT hold against another
connection that restores the parameters after the claim commits (§5).

adversarial passes over the red phase, VETO LEVANTADO on the eighth, approved

## 1. What the train does

**A1 — a purge that does not hold is refused.** The claim purges
`canonical_params` and trusted the UPDATE's `RowsAffected`. A trigger
restoring the column after the purge made it report one row over parameters
still there at commit, and a competitor entering while the first effect ran
consumed them again: `exec.Run` ran twice (captured, `runs=2`). The claim now
re-reads the column inside its own transaction, after the purge and before the
commit, and demands the empty string; otherwise it refuses with
`ErrApprovalEvidenceCorrupt` and the whole transaction rolls back. The re-read
scans without conversion, so a NULL left in the cell is corrupt too, not a
store that failed to answer; and a purge that affects more than one row (the
table rebuilt without its key) is corrupt. The same holds for every cell the
claim reads inside its transaction except `principal_id`, which is nullable by
design (an action may carry no principal; the preview comparison judges it):
the story's first read (`effect_class`, `op_namespace`, `op_name`), the
parameters and preview before the purge, the approval status and the action
state after it. A NULL in any of them, or a status/state outside its domain
(`'BOGUS'`), is corrupt evidence — never «unreadable» and never a legitimate
loss of authority (`ErrApprovalNoLongerApproved`). The effect class read back must fall in the STORED
domain (`storedEffectClassInDomain`): the sealed enum of `action.EffectClass`
plus the E1 placeholder «unclassified», which `action.NewEnvelope` writes into
every envelope and `brain.classifyEffect` returns when no classifier is wired
— a legitimate stored value, not corruption. An empty or unknown class is
corrupt even when the same hand rewrote the preview and its digest to agree;
without the check the claim committed and handed the parameters out. A first
version checked the enum alone and broke two approved tests that park an
«unclassified» action; it was withdrawn before delivery and the director chose
the stored domain (2026-09-19). The fourth diff pass
enumerated every Scan in the claim transaction; the story's first read was the
last door of this class, and it also serves the operator's Detail door
(`approvalDetail`). Under a
persistent restoring trigger both claims are refused and nothing runs — zero
executions, the director's accepted outcome. Its scope is the claim's own
transaction; §5 states what it does not cover.

**A2 + P2-4 — one table for what a webhook_call closes on.** The tool now
observes httptrace `GotConn`, the one signal that proves no request byte left
before it (Go 1.26.6: `Transport.getConn` fires it only once `dialConn`,
TLS handshake included, handed a connection over). Every error past `Do`
carries exactly one class:

| Wire fact | Class | Closes on |
| --- | --- | --- |
| no connection obtained (dial refused, handshake never completed, shield, context ended first) | `ErrNotSent` | FAILED |
| connection obtained, no answer | `ErrDeliveryUnknown` | OUTCOME_UNKNOWN |
| the receiver answered, not with a usable success (status < 200 or > 299, a refused redirect, an unreadable or oversized 2xx body) | `ErrEffectDelivered` | OUTCOME_UNKNOWN |
| the receiver answered 2xx | — | SUCCEEDED |

A clean `WroteRequest` — the observation the tool used before — proves
nothing: `Request.write` fires it from a deferred call, before `writeLoop`'s
final flush. `CloseStateAfterRun` checks the three classes first, then the
ended-context arm, so a handshake that never completed closes FAILED even when
the run ended on a deadline. The approved path and the brain path both call it;
neither changed its classification code.

**The sentinel texts say only what is true of every member.**
`ErrDeliveryUnknown`: «a connection was obtained and no answer was read;
whether the request left is not known». `ErrNotSent`: «no connection was
obtained; nothing was sent». `ErrEffectDelivered` keeps its name and changed
its text twice in this train. «…its answer was not read» was false once the
class covered answers whose status WAS read. «the request was delivered and no
successful answer came back» was false for an EARLY answer: the diff pass
executed a receiver that read 162 of 33 554 442 bytes and answered 413, and
the text still said «delivered». What is true of every member — non-2xx, a
refused redirect (a 3xx answer), an oversized or unreadable 2xx — is that the
receiver ANSWERED: «tool: the receiver answered and the answer was not a
usable success». `TestWebhookCall_anEarlyAnswerIsNotADeliveryClaim` pins that
exact text over the early-413 reproduction (red 5 of 5 on the previous text,
`green/red-early-413.txt`). Its handler reads 162 bytes and answers: the
earliness is by construction of the handler, not observed at the socket. No test pinned either old literal; they survive
only in the paper's red captures of base, which record what base printed.

**The log field `delivery`, an observable-surface change, declared.** The
cage-denial record in `AgentBrain.runTool` carried a boolean `delivered`,
which read false for a connection obtained with no answer — a claim nobody can
make. It now carries `delivery`: `response_read`, `unknown`, `not_sent` or
`not_observed` (`deliveryOf`, `internal/brain/agent.go`). No consumer of the
old field exists in the repository (grep); an operator's log query on
`delivered` stops matching. `TestRunTool_theCageDenialLogsWhatTheWireEstablished`
drives the three values the real tool can reach through that record
(`response_read` by a refused redirect, `not_sent` by a shield refusal of a
TEST-NET address, `not_observed` by a host off the allow-list) and
`TestDeliveryOf_namesEveryClass` pins all four; `unknown` is not reachable
through a cage denial today (no cage or shield refusal fires after a
connection and before an answer).

**A3 — the crash close owns only what it may.** `crashOrphanPredicate`
excluded eight states while the crash pass's SELECT excluded nine:
`AUTHORIZED` was missing, so a row that became AUTHORIZED between the SELECT
and the UPDATE — a tool now running — was closed FAILED with a crash receipt.
The UPDATE's own WHERE now excludes it.

**The sister, seen before law.** The claim judged the law before comparing the
caller's snapshot, so a row that moved under the caller was published
`invalidated`, whose literal says rejecting still works. The snapshot is now
compared first. Reachable by out-of-band tampering only: with the snapshot
APPROVED no production writer moves a compared column.

**X2 and ternaOf — one class per refusal.** The history row and the operation
triple were read with typed Scans, and a conversion failure (text in an
integer column) was wrapped unreadable — bytes that are there and never verify,
published as transient. Both are now scanned as text and parsed in Go: a value
that does not parse, or is NULL, is corrupt; only a failed Scan is unreadable.

## 5. Open, filed for v0.15.2 — single consumption against a post-commit restore

Director's decision on the diff pass: scope and file, no redesign.

**Declared, predicted, not executed — a future effect class.** An effect class
written by a newer binary without a schema bump would be outside this binary's
stored domain and read as corrupt evidence here: fail-closed, no execution.

**Reproduction (executed by the diff pass's adversary, not by this train):**
approve a request; call `ExecuteApprovedAction`; while its `exec.Run` is in

second real connection writes the original bytes back into

trigger) is refused. Nothing here stops a writer that restores after the

to `docs/HANDOFF.md` and the release notes through block C. **OPEN, filed for
v0.15.2.** The two godocs that promised more are scoped: `ExecuteApprovedAction`
(`internal/app/approvals.go`) and `approvalsExecute` (`internal/cli/approvals.go`,
the `korvun approvals execute` door, through which the diff pass captured the
