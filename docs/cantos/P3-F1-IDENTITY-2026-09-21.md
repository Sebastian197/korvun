## Result

Every ingress door now issues an OPAQUE authenticated capability at the exact
point where its own authentication succeeds, and only there. The capability
crosses the adapter, the router queue and the brain, and the coordinator
resolves it into signed identity evidence that lands in the SAME transaction as
the action it belongs to. A channel LABEL is no longer an identity, a sender
field is no longer a principal, and a shared credential asserts a requester and
a subject claim — never a human.

Action schema 13 → 14. No dependency file changed.

## The Windows timeout: a ceiling inside the runner's own variance

The pull request's `quality (windows-latest)` check FAILED, and the first
reading of it was WRONG. It is corrected here with the measurements that
correct it.

`internal/action/sqlite` died with «panic: test timed out after 10m0s»
(run 35585791481, job 106288699401). The test holding the clock was
`TestResourceBound_thousandsOfCyclesStayBounded` at 5m33s — a mould this train
does not touch.

**The first reading was "master runs 165 milliseconds inside the limit".** That
came from one capture: master `551f9770`, this branch's own base, finishing
that package in 599.835s against 600. It is a real capture, and as a
description of the package it is misleading.

**What four runs of master actually show**, same package, same runner label:

| master | `internal/action/sqlite`, windows |
| --- | --- |
| `551f9770` | **599.835 s** |
| `adb44231` | 368.212 s |
| `55537f34` | 326.183 s |
| `d2a36fdb` | 300.802 s |

The duration VARIES by nearly a factor of two between runs of the same suite.
The package does not sit at the ceiling; the ceiling sits INSIDE the range the
runner produces. So the gate passed or failed according to which machine the
job landed on — and `551f9770`, the slowest of the four, is the base this
branch was cut from.

**That 600 was never a decision of ours.** Neither `.github/workflows/quality.yml`
nor the `Makefile` passed `-timeout`, so Go's default of 10m per package
governed, inherited rather than chosen. A ceiling nobody picked, falling inside
the natural spread of the runner, is a NON-DETERMINISTIC gate — which is worse
than a strict one, because it teaches people to re-run rather than to read.

**What this train contributes, measured rather than guessed:** the six new
sqlite moulds cost 4.89s summed locally (0.75 + 1.99 + 0.39 + 1.08 + 0.33 +
0.35), and the phase's own `identity_phase1_test.go` adds more. That pushes the
whole distribution up; it is not what put a single run at 600.

**The cure, by the director's decision of 2026-09-21:** `-timeout 30m`, written
EXPLICITLY at all FOUR invocations — the `Test` step and the `Coverage gate`
step of `quality.yml`, and the `test` and `cover` targets of the `Makefile` —
each with the reason beside it. **The green run of this branch did the same
package in 383.857 s** (run 35588963677, job 106298764223), which is the
variance, not the cure: the cure is that 383 and 599 now both pass.

**What the cure does NOT do**, said plainly: it speeds nothing up and hides
nothing. A genuinely hung test still dies, at 30m instead of 10m. What stops
happening is a verdict decided by which runner answered.

**No mould, and why:** this is a CI change, with no Go branch to redden. Its
evidence is the five captures above, each cited with its run, and the local
measurement of the six moulds. It entered AFTER the adversary's pass, by the
director's decision, and is declared here rather than folded in quietly.

## What is NOT in this phase

Enforcement beyond what the spec fixes, strict refusal to run without durable
identity storage, credential rotation, OIDC, mTLS and delegated authority are
outside Phase 1 and stated in the spec's own residuals. Shared credentials and
provider subjects do not establish personal identity, and this phase does not
claim they do.
