# The Wails pin, and the rule that had nothing enforcing it

Date: 2026-09-22. Status: **IMPLEMENTED**, gate green, one adversary pass behind
it. VERIFIED is the gate's word and ACCEPTED is the reviewer's; this canto
claims neither, and the external gate has not run. CI-only train: no Go source
line moves.

Written under the director's two permanent norms of 2026-09-22 — «ninguna cura
se escribe mirando solo el fallo» and «todo diseño lleva su plan de fallos».
§1 is the environment the first demands, §2 its failure mode, §3 the moulds,

## 1 · Environment

Graphify does not map CI: the surface is `Makefile`, `.github/workflows/` and
`go.mod`, none of them Go symbols. Directed search over the tree instead,
declared rather than implied.

**What names a Wails version, and who reads it:**

- `go.mod:9` — `github.com/wailsapp/wails/v2 v2.16.0`. The LIBRARY the desktop
  binary links. Dependabot moves this one.
- `.github/workflows/release-desktop.yml:156` — `go install …/cmd/wails@v…`.
  The CLI that BUILDS the published artifacts. Nothing moved it automatically.
- `.github/workflows/release-desktop.yml:77` and `:154`, `Makefile:84` — three
  labels and comments naming a version, read by humans only.
- `docs/adr/0036-wails-v2-dependency.md` — names `v2.13.0` and `v2.15.0` as
  HISTORY, and must keep naming them.

**Who runs the pin:** `release-desktop.yml` alone, and it fires only on a `v*`
tag push or a manual dispatch. Nothing on a pull request installs the CLI, which
is why the drift survived two bumps.

**How it was found:** by hand, reading #56's diff against ADR-0036. Not by any
gate. That is the whole reason this train exists.

## 2 · How this cure could itself break something

- **A guard over version strings can demand that HISTORY be rewritten.**
  ADR-0036 records `v2.13.0` and `v2.15.0` deliberately. Cured by scope: only
  `Makefile`, `.github/workflows/` and `.github/actions/` have their labels
  judged. Inside a build file a version string is an instruction rather than
  prose, so a contrasting version fails there on purpose; the exemption is for
  documentation, and the ADR now says exactly that.
- **A guard can fail OPEN.** Every arm that cannot read its inputs raises and
  exits 2, distinct from the 1 that means drift: an unreadable or ambiguous
  `go.mod`, a `replace` for Wails, an absent `Makefile`, an unreadable file on
  any scanned surface. All have rows.
- **A guard can be enforced where nobody meets it.** Placing it only in
  `make quality` would leave it out of the pull-request checks, because
  `quality.yml` does not run `make quality` — it runs steps. Found while
  writing the Makefile comment, whose first draft claimed the target reddened
  pull requests; the claim was false until `quality.yml` gained its own step.
- **A guard can be masked by a step before it.** A job stops at its first red,
  so a guard placed after `Install tools`, `Build`, `Lint` and an apt/brew/choco
  install would go unreported on any runner where one of those fails — the very
  moment a stale pin is easiest to miss. It runs third, right after checkout and
  `setup-go`, and needs neither Go nor sqlite3.
- **A guard can trip over its own fixtures.** `scripts/` is on the install-pin
  surface and the attack fixtures name old versions by necessity. They compose
  their pins from `CLI_MODULE` instead of spelling one, so the surface stays
  wide with no exemption in production code. The first shape of those fixtures
  did spell them and the guard went red over its own tests; the fixtures moved,
  the surface did not.

Fourteen mutations, each applied ALONE on a copy under the scratchpad, its red
captured, the copy discarded. The tree was never mutated.

**Two mutations came back GREEN, and each cost a change to the code.** By the
doctrine a mould whose mutation does not redden it is the finding.

1. A negative lookahead `(?!/)` had been written to stop the CLI module path
   from matching the library's. Removing it reddened nothing: the mandatory
   `\s+` after the module path already does that work, because the CLI path
   carries a `/` there and not a space. **Deleted** rather than kept as
   decoration; the comment names what actually guards; M5 was re-aimed at the
   separator, where it reddens.
2. Widening the letrero surface reddened nothing, because `scan` looped the
   install-pin files and merely ASKED whether each was governed — so the prose
   exemption was really enforced by the pin surface while the letrero function
   claimed it. **The two surfaces were made disjoint** (`governed_files` and
   `pin_only_files`), each looped in its own right, so each guarantee now lives
   in the function that names it. M8 and M13-bis redden only after that change.

Evidence level, honest: **in-process**, over temporary directories. The guard's
behaviour on the REAL tree is proved by the gate step that runs it — and it was
red on this tree before the cure, naming all four sites, which is the only
capture here taken from the real thing.

## 4 · The class, not the instance

The fault's class is «a version that two places must agree on, where only one of
them moves automatically». Its members:

- **The Wails library and its build-time CLI.** Broken twice, by #34 and by
  #56. **CURED here**, by a guard on the pull-request gate.
- **`modernc.org/sqlite` and `modernc.org/libc`.** The same shape: the upstream
  requires downstream `go.mod` files to pin the libc version its own `go.mod`
  names. It holds today (both `v1.75.7`, checked 2026-09-22) and Dependabot
  groups them, so both move together. **NOT cured, and NOT filed as a defect**:
  nothing has broken it, and a guard for a pairing one tool already keeps would
  be speculative. Named here so the next person sees the shape.
- **`website/scripts/apply-webpackbar-compat.mjs` against webpackbar.** Already
  guarded, by a version fence that throws — which is precisely what turned #55
  red instead of silently patching a shape it had not read. **Filed** for its
  own train in `docs/HANDOFF.md`.

Nothing of this class is cured in silence: one closed, two named.

## 5 · The adversarial pass

One pass, `.claude/adversary/wails-pin-verdict.md`, verbatim and written to disk
before any cure of it began. It returned **VETO MANTENIDO** with one P1, seven
P2 and ten P3, and it has NOT read the cures — by the director's rule of one
internal pass per train, what a pass finds is cured in the same tree and
declared by name.

**The P1 was the one that mattered.** Three letreros promised «it reddens the
bump's own pull request», and that promise is carried entirely by `main()`'s
exit code — which no row observed. The auditor neutralised `main`'s returns,
ran the suite green, and walked a fully drifted tree past the guard. The suite
would have passed identically if the dangerous branch had not existed. Cured by
the `TheProductionDoor` class, whose four rows read the code and both streams,
with M6 and M7 as their executed reds.

**Two of its P2s were arithmetic I had not executed** (Rule 2h), and both are
corrected in the ADR and here: the `v2/` trees hold **1036** blobs, not 1037 —
my count included a `TRUNCATED=false` line my own command had appended; and the
`webkit2_41` gating is in **eight** files, not nine — I counted a section header
for a file that carries only the gtk line. Both re-derived from the primary
source before correcting.

**One was a false sentence about the leak** (Tone law): «every C string the
darwin and linux frontends allocated leaked» is wider than the defect. Only
strings routed through `Calloc.String` leaked; `Run`, `ExecJS` and `SetTitle`
allocate and free explicitly and `v2.16.0` does not touch them. Scoped.

**One was the same false causal claim, surviving in the more permanent
document**: the Makefile comment had been corrected to say that `quality.yml`'s
step is what reddens a pull request, but the ADR still said «runs in `make
quality`, **so** it reddens…». `quality.yml` invokes no `make`. Corrected.

The rest, cured in this tree: the scan surface widened to composite actions,
`scripts/` and `Dockerfile*`, with the affirmative message naming what it
scanned; a `replace` for Wails refused rather than read past; an absent or
non-file `Makefile` refused; a named failure for any unreadable scanned file;
the letrero matcher requiring the version to be ATTACHED to the word `wails`
rather than merely sharing its line, and captured WHOLE so a `v2.16.0-rc1` is
never reported against its own prefix; versions compared with an optional
leading `v`; the printed version taken from the value already judged rather than
re-read; the step moved to the head of the job with `set -euo pipefail` written
out; a substring assert tightened to a prefix; and the fixture shapes extended
to several workflow files, the `.yaml` extension, and two pins disagreeing.

**Two of its findings changed this canto rather than the code.** A sentence here
located a symbol by «four lines above», which CLAUDE.md forbids outright and
which was also false in direction and distance; it is gone. And the declared
M5-bis mutation did not reproduce from its own wording — the table above now
carries the literal that reddens.

**What it could not verify, carried forward rather than dressed up:** whether
`quality` is a required check in branch protection (the letreros say «reddens
the pull request», which holds either way, and none of them says «blocks the
merge»); and the guard's behaviour on a Linux or Windows Python, all local runs
being Python 3.11.9 on macOS — the CI step is what exercises the other two.

**Its P3-10 is the director's call, not cured either way:** the webpackbar
filing in `docs/HANDOFF.md` concerns another dependency and another train. It
rides this branch as its OWN commit, so it can be read and reverted alone.

## 6 · The five questions

1. *Does any sentence claim more than the code and the captures show?* Three
   did, and all three were found by the pass rather than by me: the two counts,
   the leak's scope, and the ADR's «so». Corrected at the source, not softened.
2. *Does any comment cite a symbol that does not exist?* The three moved
   letreros were re-read at `v2.16.0` before their versions changed: `apt.go`
   still lists `libgtk-3-dev`, `libwebkit2gtk`, `build-essential` and
   `pkg-config`; the `webkit2_41` cgo lines are still in eight files of
   `internal/frontend/desktop/linux`. Only the version in each citation moved.
3. *Does any mould enter through a private function instead of the production
   door?* Four rows now enter through `main()` — that gap was the P1.
   `WailsPinAttacks` still calls `scan` and `library_version` directly, which is
   where the taxonomy lives; both are exported names of this module.
4. *Did I cure ONE member of a class that has several?* See §4 — one cured, two
   named, neither silent. And within the guard itself, the «guarantee living in
   a function that does not name it» class bit twice and was cured
   structurally, not case by case.
5. *Did any cure enter without its mould and its captured red?* No: fourteen
   mutations with their reds, plus the two that came back green and each cost a
   change to the code.
