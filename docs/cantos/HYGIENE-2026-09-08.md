### Do they reach the published binaries? No. What that rests on

The first draft of this batch answered that question with a `go list
-deps` sweep described as "the six published combinations with the real
release tags". The adversary pass showed the description was wrong on
three counts, and it was right on all three:

- `.goreleaser.yaml` publishes SIX targets of `./cmd/korvun` ONLY, with
  `CGO_ENABLED=0` and NO `-tags`.
- `release-desktop.yml` publishes THREE desktop families, not six:
  `darwin_universal`, `windows_amd64`, `linux_amd64`.
- a cross-GOOS `go list` from macOS runs with `CGO_ENABLED=0` by
  default, which drops wails' cgo Linux frontend and therefore does not
  reproduce the closure the published Linux build has.

The answer stands, on evidence that does not depend on reproducing a
build configuration:

1. **No Go file in this repository imports `golang.org/x/crypto`.**
   `SOURCE` — `grep -rn "golang.org/x/crypto" --include=*.go .` returns
   nothing.
2. **No package in this module's own closure imports `ssh` or
   `openpgp`, under any tag and any GOOS.** That is what `go mod why`
   measures — it resolves the main module's package graph with
   `imports.AnyTags()`, so "main module does not need package" is a
   statement over every build configuration at once.

   It is NOT "nothing anywhere imports them", and the first draft of
   this canto wrote that stronger sentence, which is false:
   `github.com/go-git/go-git/v5` imports `golang.org/x/crypto/ssh` and
   reaches this repository's MODULE graph through wails. The repository
   already knew it — `docs/notes/dependabot-triage-2026-07-19.md:17`
   says "wails CLI tooling (go-git → ssh); no Korvun binary links it" —
   so the canto had been contradicting a note in its own tree.
   Corrected: the importer exists in the module graph, it is wails' CLI
   tooling, and it is outside the package closure of everything this
   repository builds.
3. **The doors into this module's own closure that this sweep found**
   are `golang.org/x/crypto/acme` and `acme/autocert` — two packages,
   not one, and the first draft said "exactly ONE door" while counting
   doors it had not enumerated. Both are imported by `labstack/echo/v4`,
   reached only through wails' devserver, which is `//go:build dev` — a
   tag no published build sets.

   Other modules in the graph import other `x/crypto` packages. `SOURCE`
   — `grep -rn "golang.org/x/crypto" $GOMODCACHE/golang.org/x/net@v0.57.0/quic/`
   returns FOUR: `chacha20`, `chacha20poly1305`, `cryptobyte` and
   `hkdf`. A previous draft of this very sentence listed three: the
   enumeration written to cure a closed enumeration was itself short by
   one, which is the third time this batch has reproduced that shape and
   the reason the sentence above says "that this sweep found" instead of
   "the only".
4. The six published `./cmd/korvun` targets, measured in their OWN
   configuration (`CGO_ENABLED=0`, no tags): zero packages of the module
   in every one. The only `golang.org/x/crypto/*` paths that appear
   anywhere are `vendor/golang.org/x/crypto/…`, the Go toolchain's own
   vendored copy inside the standard library — a different thing from
   the module this batch bumps.

So no STOP was owed to the director, and the bump is a version cure for
what OSV and Scorecard measure, not a reachability cure.

**`govulncheck` proves nothing here, and is not offered as if it did.**
It is reachability-based and no Go file imports the module, so it
answered "No vulnerabilities found" before the bump, after it, and would
answer the same at any version. It is run because the standing law

**What survives:** GO-2026-5932. `openpgp/` is still present in v0.56.0
— the bump does not remove the package — and there will never be a fixed

What replaces it is a probe that can FAIL, which the previous draft's
evidence could not. That draft read the two call sites and concluded
"`qs@6.16.0` accepts all five". The reading was true and the check was
worthless: `qs/lib/parse.js`'s `normalizeParseOptions` ignores unknown
keys in silence and fills absent ones with defaults, so "accepts all

five and silently degraded to `depth: 5` and `arrayLimit: 20`. A check
that cannot go red is not evidence — the adversary pass named it class

The call sites, `SOURCE`:

- `website/node_modules/body-parser/lib/types/urlencoded.js:169-175`
  passes `allowPrototypes`, `arrayLimit`, `depth`, `strictDepth`,
  `parameterLimit`;
- `website/node_modules/express/lib/utils.js:288-293` passes
  `allowPrototypes` and `arrayLimit`.

And what the installed version DOES with them. `EXECUTION` — the probe
is a NAMED SCRIPT, `probe-qs.js`, kept outside the repository (session
scratchpad) and reproduced in full here so a reviewer can re-run it. It
takes the path of the `qs` package as `argv[2]`, computes EVERY verdict
from the result, and exits non-zero when any of the five is not honoured:

```js
const qsPath = process.argv[2];
const qs = require(qsPath);
const own = (o, k) => Object.prototype.hasOwnProperty.call(o, k);
let red = 0;
const say = (name, ok, detail) => {
  if (!ok) red++;
  console.log((name + ":").padEnd(17), (ok ? "honoured -> " : "NOT honoured -> ") + detail);
};
console.log("qs version:", require(qsPath + "/package.json").version);
try {
  qs.parse("a[b][c][d][e][f][g]=1", {allowPrototypes:true, arrayLimit:5, depth:2, strictDepth:true, parameterLimit:10});
  say("strictDepth", false, "no throw");
} catch (e) {
  say("strictDepth", e instanceof RangeError, e.constructor.name + ": " + e.message);
}
const a = qs.parse("a[0]=x&a[1]=y&a[2]=z", {arrayLimit: 1});
say("arrayLimit", !Array.isArray(a.a), Array.isArray(a.a) ? "still an array" : "object, keys=" + Object.keys(a.a));
const p = qs.parse("a=1&b=2&c=3", {parameterLimit: 2});
say("parameterLimit", Object.keys(p).length === 2, Object.keys(p).length + " keys kept");
const d = qs.parse("a[b][c][d]=1", {depth: 1});
const collapsed = !(d.a && d.a.b && typeof d.a.b === "object" && own(d.a.b, "c") && typeof d.a.b.c === "object");
say("depth", collapsed, JSON.stringify(d));
const ap = qs.parse("a[hasOwnProperty]=x", {allowPrototypes: true});
say("allowPrototypes", !!ap.a && own(ap.a, "hasOwnProperty") && ap.a.hasOwnProperty === "x", JSON.stringify(ap));
console.log(red === 0 ? "VERDICT: all five honoured" : "VERDICT: " + red + " NOT honoured");
process.exit(red === 0 ? 0 : 1);
```

**Why the script is reproduced rather than summarised.** The version
before this one printed the word `honoured` as a LITERAL for `depth` and
`allowPrototypes` — two of the five verdicts did not depend on any
result, so a `qs` that had dropped either option would have printed
"honoured" and exited 0. The canto then generalised one executed
mutation into "a version which dropped one would be caught", which was
false for two of five. That is class (d) inside the cure written to kill
class (d), and the fifth adversarial pass found it by reading the script
the fourth pass had asked for. Both verdicts are now computed, and the
script exits non-zero on red instead of leaving the judgement to a human
comparing two blocks of text.
