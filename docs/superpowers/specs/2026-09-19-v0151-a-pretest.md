## 3. The one table (A2 + P2-4 designed together, as ordered)

`CloseStateAfterRun` keeps ONE table. Axes: what the wire reported, the status
class when an answer arrived, the error kind when none did.

| Wire fact | Answer / error | Closes on |
| --- | --- | --- |
| no connection obtained (`GotConn` never fired: dial refused, TLS handshake never completed, shield/cage refusal before the dial) | any error, a deadline or a cancellation included | **FAILED** |
| connection obtained, no response | ANY error (deadline, cancellation, reset, broken pipe, a dead pooled connection whose retry cannot re-dial) | **OUTCOME_UNKNOWN**, sentinel `ErrDeliveryUnknown` — delivery is NOT claimed |
| response received | status 200–299 | **SUCCEEDED** |
| response received | status < 200 or > 299 (1xx, every 3xx, 4xx, 5xx), or the body cannot be read, or it exceeds the cap | **OUTCOME_UNKNOWN**, sentinel `ErrEffectDelivered` — a response proves the receiver read the request |
| a tool that does not observe the wire | ended context | OUTCOME_UNKNOWN (unchanged) |
| a tool that does not observe the wire | any other error | FAILED (unchanged) |

Planned shape of the cure (for the green phase, subject to this review):
webhook_call observes httptrace `GotConn`. When `Do` fails and `GotConn`
never fired, it wraps a new sentinel (working name `tool.ErrNotSent`) →
FAILED. When `GotConn` fired and no response arrived, it wraps a second new
sentinel, `tool.ErrDeliveryUnknown`, whose text claims neither delivery nor
non-delivery → OUTCOME_UNKNOWN. `ErrEffectDelivered` is kept ONLY where a
response was read: a status `< 200 || > 299`, an unreadable or oversized
body, and the cage's refused redirect through an EXPLICIT arm in Do's error
block — `errors.Is(err, ErrRedirectRefused)` ⇒ wrap `ErrEffectDelivered`
(Delta 4, F2): `CheckRedirect` runs over a response, so the host has the
payload. The base's assertion «a response arrived for a request the wire never
reported writing» is DROPPED by the cure (Delta 5): a response implies
`GotConn` fired, the WroteRequest observation it guarded is removed, and no
test reddens when it changes class (the adversary's mutation B7, exit 0). `CloseStateAfterRun` checks
`ErrEffectDelivered`, then `ErrDeliveryUnknown`, then `ErrNotSent` → FAILED,
then the ended-context arm.

Why a clean `WroteRequest` is NOT proof of delivery either (Delta 2, found
while building the P2-1 mould, read in Go 1.26.6 source): `Request.write`
(`net/http/request.go`) fires `trace.WroteRequest` from a deferred call with
the error of `write` itself, and `persistConn.writeLoop`
(`net/http/transport.go`) flushes the bufio writer only AFTER `write`
returned. A small body sits in the buffer when `WroteRequest{Err: nil}` fires;
the flush can then fail with zero bytes out. The P2-1 mould captures it: a
dead pooled connection, EPIPE on flush, retry, refused re-dial — and today's
error reads «the request was delivered». Only a response read proves the
receiver got the request. For a POST the transport retries only on
`nothingWrittenError` (`shouldRetryRequest`: a non-replayable request with a
body is retried only when that attempt wrote zero bytes), so a retry never
hides a delivered attempt.

Why `GotConn` and not `WroteHeaders` (adversary F3): `WroteHeaders` fires
after the headers enter the transport's bufio, before the flush, and a long
request line may already have been read in part by the receiver. `GotConn`
proves no byte left, verified in Go 1.26.6 source: `Transport.getConn` fires
`trace.GotConn` only when the result carries a connection (`r.pc != nil`),
after `dialConn` returned; `dialConn` runs `addTLS` (the handshake) before
returning; the request is written by the persistConn's `writeLoop` only after
`roundTrip` holds the connection. The caged transport sets no `Proxy` and a
custom `DialContext` without `ForceAttemptHTTP2`, so neither a proxy CONNECT
nor an HTTP/2 path writes before `GotConn`. On the cancellation path
`getConn` returns `ctx.Done()` without firing `GotConn`, which is FAILED —
correct, since the handshake had not finished. `internal/app/approvals.go` and
`internal/brain/agent.go` are expected NOT to change: both already call the
one classifier. The brain path is touched by moulds only (a declared touch
outside the block's directories, required by «en las DOS rutas»).
