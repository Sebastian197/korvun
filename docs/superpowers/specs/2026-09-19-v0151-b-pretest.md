## 2. Production paths traced

- **P2-7.** (Paragraph kept for the trace; the guarantee it served was
  replaced by the director's ruling.) `internal/app/app.go` (Build) mounts `controlapi.RegisterApprovals`
  on `adminServer`, which binds `cfg.ObservabilitySettings()` (default
  `config.DefaultObservabilityAddr` = `127.0.0.1:2112`, operator may set
  `0.0.0.0:PORT`). `approvalsAuth` (`internal/controlapi/approvals.go`) checks
  the bearer and nothing about the peer. The adapter's `approvalsOperator`
  (`internal/app/approvals_adapter.go`) resolves the provenance registry
  `"desktop": console / CredentialLoopbackInProcess` for every call and builds
  the operator envelope with `Source{operator, desktop, desktop}`.
  `recordDecisionActTx` (`internal/action/sqlite/approvals.go`) persists that
  source in the `actions` row. **Finding, measured:** it persists NO `evidence`
  row, so the credential itself never reaches the ledger; the durable form of the
  «loopback, in-process» claim is the act's source columns. The first version of
  the P2-7 mould counted evidence rows and was green before any cure; it was
  re-pointed at the source columns and is now red (§5).
- **P2-8.** `nameRead` and `nameTouch` call `currentLawDigest()`, which resolves
  `cfg.Brains[0]`. The brain that parked the request is already known to
  `resolveLawFor` (`principal_brain_<name>`).
- **P2-9.** `decideApprovalWithLaw` → `transitionTx`. `transitionTx` wraps an
  exec failure raw, discards the `RowsAffected` error (`n, _ :=`), and returns an
  untyped «row not in expected state» for zero rows. On APPROVE the caller wraps
  either with `ErrApprovalActionNotPending` → `nameTouch` → `already_closed`. On
  REJECT (`rejectParkedActionTx`) both come back untyped → `nameTouch` default →
  `unavailable`, which is the wrong half for the zero-rows case (sister).
- **P2-10.** `ask()` then `send()` in `Approvals.tsx`: a 200 is `executed` unless
  `outcome === 'failed'` (approve) and always `rejected` (reject);
  `DecisionState` renders the four names only through `OUTCOME_TEXT` or the
  `switch`, where they are absent, so they fall to `UNKNOWN_NAME_TITLE`.
- **P2-6.** `approvalTx` returns `scanApproval`'s error bare to the decide and
  the sweep; `ListApprovals` does the same. `GetApproval` and `approvalTx0` type
  EVERY Scan error as corrupt — including a cancelled context, because
  database/sql defers a query's error to Scan (captured: `GetApproval` under a
  cancelled context answers `…stored evidence no longer verifies: context
  canceled`, and the adapter's Reject then answers `evidence_corrupt`). Block
  A's claim `ClaimApprovalParamsUnderDigest` already wraps every non-NotFound
  `approvalTx` error as corrupt, so it inherits the same class. The sealer:
  `approvalDigestTx` (`internal/action/sqlite/ledger.go`) returns `""` on any
  Scan error and drops `parseNullTime`'s error, so `FinishWithResult` seals an
  approved action's receipt with `approval_digest=""` over a corrupt approval
  row (captured, §5). **Correction (delta 2):** that is the Scan case only.
  With `decision_at` unparseable, the dropped `parseNullTime` error leaves
  `DecisionAt` zero and the receipt seals the digest of the approval over a
  ZERO decision instant — a history that never happened, which no row
  re-derives. The same happens on the recovery door (`RecoverPreviousLife` →
  `closeCrashOrphan` → `receiptForFinish` → `approvalDigestTx`), which the
  boot runs after wiring the sealer.
- **P2-1.** CLI `approvals show|approve|reject|execute` take the positional id
  unchecked, open the store and exit 1 on not-found; `operatorEnvelope` and the
  adapter's `approvalsOperator` build `{"approval_id":"`+id+`"}` by
  concatenation. The routes forward `r.PathValue("id")` to the seam unchecked.
  The screen prints `r.id` and `d.id` raw and interpolates the id into
  `/api/approvals/${id}` without encoding; it prints `Recibo ${receipt}` raw.
- **P2-2.** Every verb of the three families builds its own `flag.FlagSet` with
  output to stderr and `return 2` on any parse error, `-h` included; the nouns
  treat `-h` as an unknown subcommand.
