# v0.16.1 C · P1 — a committed park reported as a refusal

Date: 2026-09-22. Status: **DESIGN — RED is not open.** Base: master `32701e0`.
Ficha: «Un aparcamiento confirmado puede devolver error», in `docs/HANDOFF.md`. Elevated to **P1 by the director on 2026-09-22**
and ordered first in branch C, with its line in the v0.16.1 notes as the cure of
a serious fault.

## The fault, read in the tree

| Step | Site | What happens |
|---|---|---|
| 1 | that function's own `tx.Commit()` | `tx.Commit()` — the action, the decision, the evidence and the **approval row** are durable |
| 2 | the `return s.noteWrite(ctx)` tail of `createApprovalPartsWithIdentity` | `return s.noteWrite(ctx)` — the function's result becomes the result of unrelated housekeeping |
| 3 | `noteWrite`'s two cadence arms in `internal/action/sqlite/store.go` | every `pruneEvery` writes (512), `Prune` or `SweepExpiredApprovals` may fail and that error is returned |
| 4 | `approvalRecorder.RequestApproval` in `internal/app/approvals.go` | the caller returns `"", err` — **the approval id is dropped on the floor** |
| 5 | the executor's plain approval branch | `result.ApprovalError = err`, and control falls through |
| 6 | its fall-through denial arm | `result.Branch = BranchDenied` and a SECOND `actions` row is recorded in `StateDenied` |

**The outcome:** a `PENDING_APPROVAL` row and its `approvals` row sit in the
store waiting for a human who is never told, while the caller is told the action
was DENIED and the ledger gains a denial that never happened. Nothing is
executed — the effect is not the risk. The risk is that **the store's record and
the operator's belief disagree, permanently, with no door that reconciles them**.

**The class has four members**, all returning the same tail after their own
commit: the park's tail, `RecordAttempt`'s, `evidence.go`'s and `identity_v2.go`'s.

## The cure

`noteWrite` stops being able to speak for the write that called it. It returns
nothing; a failure inside it goes to an injected observer, nil in production
meaning «nobody is listening», wired by the app to `slog`. All four callers
return the result of their OWN transaction.

Rejected alternatives:

| Option | Verdict |
|---|---|
| Swallow the housekeeping error silently | **Rejected**: retention failing is a real fact and losing it trades one lie for one blindness |
| Run the cadence BEFORE the write's transaction | **Rejected**: its failure would then refuse a write that had not happened yet — a different lie, and it would make every park pay the sweep's latency before parking |
| **Return the write's own result; report the failure on its own channel** | **Chosen** |

### 3 · Neighbours and class siblings

All three siblings are cured by the same change, because the cure is to
`noteWrite` itself rather than to its callers:

- `RecordAttempt` — a recorded attempt reported as failed.
- the identified writer in `evidence.go` — evidence written and reported as failed.
- the authenticated writer in `identity_v2.go` — same, and the door three operator verbs use.

Each gets a row asserting its own committed write survives a failing cadence.
**Nothing of the class is cured in silence.**

### 4 · Declared and NOT covered

- **The observer is nil in production until the app wires it.** Both halves land
  in this train; if only the store half landed, the failure would be silently
  dropped, which is the «blindness» the rejected option was rejected for.
- **`pruneEvery` stays 512 and stays without a config surface.** The cure does
  not touch the cadence, only who hears it fail.
- **The `Prune`/`Sweep` errors themselves are not reclassified.** Whether a
  deterministic purge error should be `ErrApprovalUnreadable` is the SEPARATE
  ficha «El error determinista dentro de la purga se publica «unreadable»», on branch B.
- **No door reconciles a denial already written against a pending row.** Stores
  that met this bug before the cure still carry both rows. Naming a repair for
  them is not in this train; the state is named here so it is not discovered
  later as a surprise.

## Success criteria

- `make quality` green with `-race` over the whole suite, once, at the end.

## Amendment, 2026-09-22 — what the adversarial pass changed

The pass returned VETO MANTENIDO. Against THIS ficha it found two gaps, both
cured in the same tree: the FOURTH door (`identity_v2.go`) had no mould and
survived uncured with the whole suite green, and the SWEEP branch of `noteWrite`
had none either, so deleting its observer call was invisible. Both have their
mould and their executed red now.

It also found that `noteWrite`'s godoc claimed a failure «is NOT swallowed»
while the nil observer — the default — drops it, contradicting the field's own
comment in the same commit. Corrected.

Declared and not cured, from the same pass: the observer runs synchronously in
the writer's goroutine with no `recover`, so a panicking sink panics a committed
write. The production sink is `slog`. Named in the canto rather than fixed.
