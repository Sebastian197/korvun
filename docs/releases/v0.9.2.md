# Korvun v0.9.2 — Beta (patch)

A fixes-only patch: the four use-breaking findings of the exhaustive UX debt
audit of 2026-08-23 (`design-drafts/ux-debt-map.md`, wave 1 — run against the
packaged v0.9.1 build on real hardware, fresh-profile and populated-profile),
plus one process change. No new features, no schema changes.

## Fixed

- **Cables can be disconnected (B8).** The canvas edges are controlled, but
  no `onEdgesChange` handler was passed: React Flow delivers selection as
  edge changes in controlled mode, so every click on a cable was dropped and
  no gesture could ever disconnect a route — verified in both WKWebView and
  Chromium. Selection is now applied (and only selection — structure keeps
  deriving from the working copy), the selected cable paints with the accent
  token, and both Backspace and Delete remove it. The real pointer gesture
  runs against the real binary in e2e.
- **A provider change clears the orphan warmup (B6).** The model panel does
  not expose `warmup`, but a node inherited from a local template could carry
  `warmup: true` underneath — and the validator rejects warmup on cloud
  entries, walking the user into a rejected reload over a field they could
  neither see nor touch. The reducer now follows the channel panel's
  mode-follows-type pattern: switching provider to `openai-compatible`/`groq`
  or locality to `cloud` clears the inherited flag.
- **The reload trail is diagnosable and its contract pinned (B7).** A reload
  the log proved applied was once painted as "reload failed — the running
  config is unchanged"; the incident left zero trace because reload states
  lived only in memory. Every state transition now lands in the structured
  log (`reload state`, handle + state). The contract the banner depends on is
  pinned at two layers: a race-tested Go test polls the reload handle through
  the shell proxy across real ephemeral-port cutovers (the handle survives
  the port change; no phantom terminal state), and an e2e drives the
  incident's exact gesture against the real binary. The phantom did not
  reproduce at either layer; if it recurs, the log now catches it red-handed.
- **Model health is visible (N6).** A model that failed its boot probe — a
  mistyped ollama tag, a dead gateway — died as a WARN in the log while the
  UI said nothing; the user discovered the breakage mid-chat. The warmup
  outcome now reaches the UI: `/api/brains` carries a per-model health state
  (`unknown` | `warming` | `ready` | `unreachable`), the Builder's model node
  wears it as a badge (with the provider's error as its tooltip), and the
  desktop chat warns above the composer when the open conversation routes to
  a brain whose every model was observed unreachable. Only warmup-enabled
  models are probed — probing an opted-out model would cost tokens and, on a
  private brain, leak a probe to the cloud — so a never-probed model reads an
  honest `unknown`, never an invented `ready`.

## Process

- **The sixth law is in force (UX-DESIGN-FIRST + MANOS-DE-CHANO).** No
  user-visible piece opens its red phase without an approved experience
  design (`docs/superpowers/specs/UX-TEMPLATE.md`), and no release is tagged
  without a manual pass over the packaged build. The bug bash that produced
  this patch's findings is now permanent customs, not an event.

## Compatibility

No config schema changes. Configs from v0.9.0/v0.9.1 load unchanged. The
`/api/brains` response gains the additive per-model `health` /
`health_detail` fields; existing consumers are unaffected.
