# Korvun v0.9.0 — Beta

The ninth release ships the **universal model gateway**: any OpenAI-compatible
chat-completions endpoint — cloud or local — becomes a first-class Korvun model
by config alone, riding the same policy engine, privacy filter, and governed
tools as every native adapter. Design: the
[universal-model-gateway spec](../superpowers/specs/2026-08-22-universal-model-gateway.md)
and [ADR-0044](../adr/0044-universal-model-gateway.md).

## Highlights

### The universal model gateway — chat (ADR-0044, SP-A)

- **One provider, every compat endpoint.** `provider: "openai-compatible"`
  with a declared `base_url` covers DeepSeek, Moonshot/Kimi, Gemini's compat
  mode, OpenRouter, LM Studio, llama.cpp server — seven targets verified
  against their official documentation, zero code per provider. You declare
  the FULL prefix (`/v1`, `/api/v1`, `/v1beta/openai`, or none); Korvun
  appends exactly `/chat/completions` and never guesses.
- **The error grammar is a matrix, and quota is not a rate limit.** Every
  status maps to the house sentinels with declared retryability; a 429 whose
  envelope carries a code from the closed `quotaExhaustedCodes` list (OpenAI's
  billing codes, and Moonshot's `exceeded_current_quota_error` — found live in
  the release demo) is a PERMANENT "add credit" error, never retried; genuine
  rate limits keep their `Retry-After`-aware retries.
- **Redirects are refused structurally.** A 3xx answer fails the call — your
  conversation and your Authorization header can never be silently re-routed
  to a host you did not declare.
- **Key hygiene with a second belt.** The API key is never logged and never
  appears in any error; every body-derived diagnostic passes a literal
  redaction — a hostile server echoing the Bearer back gets `[REDACTED]`.
- **Duplicate entries fail loud.** Two entries in one brain with the same
  (provider, normalized `base_url`, `model_id`) are the same backend wired
  twice — rejected at boot, naming both indices.
- **Declared locality, unchanged privacy.** An entry declared `local`
  (LM Studio, llama.cpp) is eligible in private brains; one declared `cloud`
  is never contacted by them — the existing structural filter covers the new
  provider by construction, proven from the real assembly with a spy server.

### Native tool calling through the gateway (SP-B)

- **Cloud models drive governed tools.** The gateway implements the native
  tool-calling lane: `tools` on the wire, `tool_calls` parsed with their ids,
  results correlated by `tool_call_id` — and every call still passes the same
  tri-state governance gate, cages, shield, and audit as always.
- **`memory_note` from the cloud.** A cloud model can now remember through
  the gateway — filmed live in the desktop app: gpt-4o-mini (via OpenRouter)
  asked to remember, the gate authorized, `/notes` showed the note, and the
  model answered from memory. Real cost of the filmed session: about a tenth
  of a cent.
- **No capability guessing.** Korvun never probes whether a model supports
  tools; pick a tools-capable model and incapable ones answer with the
  provider's own honest 400.

### Proven against real servers

The release demos ran against real endpoints: a local llama.cpp server
(Llama 3.2 1B — a 2.1 s private-brain round-trip on a 2017 iMac), OpenRouter
in the cloud, and the on-camera desktop-app session above. DeepSeek and
Moonshot answered with their real quota errors on empty accounts — classified
exactly as the matrix promises.

## Compatibility

Fully additive. The `"openai-compatible"` provider, the seam's tool-call id
fields, and the new validations only exist when you use them — a v0.8.0
config parses and behaves exactly as before. Existing adapters (Ollama, Groq)
are byte-for-byte untouched. No new runtime dependency; `go.mod` is unchanged.

## Minor

- `ToolCall.ID` / `Message.ToolCallID` join the model seam as additive,
  optional correlation fields; the agent loop threads them when present.
- The success-body read of the new adapter is bounded at 4 MiB — deliberately
  stricter than the native adapters until the retrofit lands.
- `docs/CONFIGURATION.md` documents the provider with per-provider `base_url`
  examples straight from the verification table.

## Artifacts

Two families in one release, exactly as v0.8.0. `<ver>` is the version without the
leading `v` (e.g. `0.9.0`).

| Family | Artifact | Target |
|--------|----------|--------|
| Headless | `korvun_<ver>_{linux,darwin}_{amd64,arm64}.tar.gz`, `korvun_<ver>_windows_{amd64,arm64}.zip` | server / CLI, six OS·arch |
| Headless | `checksums.txt` + `.sig` + `.pem`, per-archive `*.sbom.json` | signed manifest + SBOMs |
| Desktop | `korvun-desktop_<ver>_darwin_universal.dmg` | macOS universal app |
| Desktop | `korvun-desktop_<ver>_windows_amd64-installer.exe` | Windows NSIS installer |
| Desktop | `korvun-desktop_<ver>_linux_amd64.tar.gz` | Linux binary + `.desktop` |
| Desktop | `checksums-desktop.txt` + `.sig` + `.pem` | signed desktop manifest |

**Draft-until-complete:** the release is born a draft and is published only once
**both** families and their signatures are present, so a broken desktop build can never
expose a half-populated public release (ADR-0035 §8; SP7 §1e).

## Verifying this release

Both families are signed keyless with [cosign](https://github.com/sigstore/cosign)
(Sigstore), each with its own manifest. Verify the manifest signature you need, then
check your download against it.

Headless:

```sh
cosign verify-blob checksums.txt \
  --signature checksums.txt.sig \
  --certificate checksums.txt.pem \
  --certificate-identity-regexp 'https://github.com/Sebastian197/korvun/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

Desktop:

```sh
cosign verify-blob checksums-desktop.txt \
  --signature checksums-desktop.txt.sig \
  --certificate checksums-desktop.txt.pem \
  --certificate-identity-regexp 'https://github.com/Sebastian197/korvun/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

For the gateway in daily use: [`docs/CONFIGURATION.md`](../CONFIGURATION.md).
