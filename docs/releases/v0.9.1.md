# Korvun v0.9.1 — Beta (patch)

A fixes-only patch: everything here comes out of the desktop app audit of
2026-08-23 ([the audit report](../audits/2026-08-23-desktop-app-audit.md)),
which drove the packaged v0.9.0 app as a user on real hardware (macOS 13
Intel, WKWebView) and mapped what broke. No new features, no schema changes,
no re-recorded demos — the v0.9.0 gateway demo remains valid.

## Fixed

- **The Builder's token gate is gone in the desktop app.** Embedded in the
  desktop chrome, the gate was theatre: the shell proxy injects the real
  per-cycle bearer server-side (ADR-0035 §4), so any pasted string opened it
  and the real token could never be known. The embedded Builder now loads
  straight to the canvas; a direct browser keeps the gate unchanged.
- **The Builder tells the truth about `openai-compatible`.** The model
  panel's provider list did not know the v0.9.0 gateway provider, so a compat
  entry displayed as "ollama" and editing it could corrupt the entry. The
  provider now shows under its real name and the panel exposes `base_url`
  (required for compat, optional adapter override otherwise).
- **Desktop configs always carry the `admin` block.** Without it the core
  mounts neither `/api/config` nor `/builder` and the Builder tab was a 404
  trap. Fresh installs already shipped the block in the first-run template;
  existing configs without it now gain it on app mount (`EnsureAdminBlock`,
  token env `KORVUN_ADMIN_TOKEN` — the per-cycle bearer stays in-process,
  and the admin bind stays loopback as before).
- **The canvas answers.** Dropping a model on the empty canvas was a silent
  no-op (models exist only inside brains — NC-6, unchanged); the drop now
  paints an honest hint, and the palette hint stops instructing the wrong
  gesture. The properties panel — which had no close path at all — closes
  with an X, Escape, and a click outside.
- **The desktop finally logs to a file.** A Finder-launched app has its
  stderr discarded by macOS, which made a failed boot undiagnosable. slog
  now tees to `korvun-desktop.log` next to `korvun.json` in the profile
  directory (simple one-deep rotation at 5 MiB).
- **The webhook channel is findable.** The channel wizard gains a third
  card: it explains that webhook is configured in the Builder and lands you
  there. The full webhook wizard step is registered for v0.10.

## Known limitation

The WKWebView **native** drag gesture is not coverable in CI (the e2e suite
drives Chromium with synthesized drag events); the audit verified the gesture
manually on macOS 13 hardware, where it works. Manual verification remains
the check for WebView-specific drag behavior.

## Compatibility

No config schema changes. Configs from v0.9.0 load unchanged; an admin-less
config is upgraded in place on desktop mount (unknown fields preserved
verbatim, atomic write).
