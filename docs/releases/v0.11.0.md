# Korvun v0.11.0 — Beta: the Action Kernel

The first release of the Execution Trust Layer era (Etapa 1 of 10). Every
tool action an agent brain takes is now born as a first-class, canonical
action — with an explainable decision recorded BEFORE any effect and a
durable record after it — while the product experience does not move one
pixel: the kernel is an invisible motor, and that invisibility was itself
the acceptance criterion, verified by the director's manual pass over the
packaged build (identical chat, plus a real customs receipt read from his
own profile).

## What the kernel does

- **Every attempt becomes an ActionEnvelope**: who asked (brain, lane,
  channel), what exactly (operation + a deterministic `sha256:` digest of
  the canonicalized parameters — same logical action, same digest, on the
  text lane and the native lane alike), and when.
- **The decision lands before the effect.** The action gate WRAPS the
  existing governed-tools decision, never replaces it: allowed calls
  record `AUTHORIZED` with their rule, rehearsed (shadow) calls record
  `SHADOWED` and still NEVER execute — the old invariant, now with a
  receipt — and denied or hallucinated tools record `DENIED` with the
  rule that refused them. An attempt the store cannot record fails
  CLOSED: no record, no effect.
- **Executions close honestly**: `SUCCEEDED`, or `FAILED` for tool errors
  and cage refusals; an interrupted run is closed as `FAILED` with a
  crash-recovery marker on the next boot — never silently re-executed.
- **One path to execution, enforced by machine**: the only caller of a
  tool's `Execute` is the kernel's Executor Registry, and a CI tripwire
  sweeps the whole tree to keep it that way forever.
- **Durable, bounded, self-managing storage**: the action ledger lives in
  the same database file as conversations but under its own schema
  lifecycle, with automatic capped retention (terminal rows only, oldest
  first — live rows are untouchable) and zero new configuration.

## The measured toll

The kernel's full cost on the hot path of a tool call — envelope, digest,
atomic record, execution, terminal close on a real SQLite store — measures
**~0.85–1.06 ms per call** on the reference machine (six samples), far
under the 5 ms p95 ceiling the design spec bounds it to. With recording
off, the adapted path shows no regression against the pre-kernel baseline.

## Fuzzed from birth

The kernel's parsers were born fuzzed (the house security plan's first
piece, brought forward by the director's call): native Go fuzz targets pin
the canonicalizer (never a panic, deterministic, idempotent) and the
digest (stable per tuple; length-prefixed field boundaries can never
collide), with the seed corpus versioned in the tree and a seconds-long
fuzz smoke wired INTO `make quality` as a permanent gate. First smokes:
~590k executions combined, zero findings. Long campaigns remain a
documented nightly task.

## Compatibility

Invisible on purpose: **zero new configuration, zero manual migration,
zero experience change**. The action tables bootstrap themselves inside
the existing storage file on first boot (their own lifecycle; conversation
data untouched); stateless deployments (no storage block) simply keep
recording off. Both lanes, shadow semantics, the protocol-leak guard,
cages, the network shield, transcripts, metrics and feeds behave exactly
as in v0.10.0 — pinned by the entire pre-existing test suite passing
unmodified.

## Verify your download

Both families ship a sha256 manifest signed with cosign (keyless,
Sigstore) and an SPDX SBOM per platform:

```sh
cosign verify-blob checksums.txt \
  --signature checksums.txt.sig \
  --certificate checksums.txt.pem \
  --certificate-identity-regexp 'https://github.com/Sebastian197/korvun/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

(Desktop family: the same command over `checksums-desktop.txt`.) Full
walkthrough: [`docs/packaging/INSTALL.md`](../packaging/INSTALL.md).
